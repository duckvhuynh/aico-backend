# AICO-003 AEO Foundations Audit

## Scope and verdict

- **Audit role:** AEO Foundations Architecture
- **Reviewed package:** ADR-007, `TENANT_DATA_BOUNDARIES.md`, `AICO_003_THREAT_TEST_PLAN.md`, `AICO_003_EVIDENCE.md`, ADR-005, and `OBSERVABILITY_AND_EVALUATION.md`
- **Authority:** `duckvhuynh/aicompanyos#3`, `duckvhuynh/aico-backend#10`, SRS TD-002/006/009, SRS-FR-092, SRS-NFR-008-010/013-016, DEC-013, and PRD-OQ-004
- **Verdict:** **Conditionally conformant as an architecture package; not implementation-, recovery-, deletion-, or alpha-ready.**

ADR-007 and the tenant-data contract preserve the AEO foundations: PostgreSQL remains authoritative, telemetry cannot authorize, causal identities remain distinct, evidence is immutable and privacy-bounded, and replay cannot fabricate certainty. Existing code and fixtures are partial reusable evidence only. Every absent surface remains owned by a later AICO issue and release-blocking when that surface enters a candidate.

DEC-013 remains open. This audit defines no final retention, signed-access, staging, preview, export, log, evidence, backup, deletion-grace, provider, or hold duration.

## Evidence retention and redaction rules

Evidence for AICO-003 and its later implementation gates MUST retain only:

- stable case/check ID, exact repository SHA, release/run/attempt/policy/fixture version references, and producer/check version;
- bounded UTC timestamps/durations, result/reason class, synthetic response digest, safe aggregate before/after counts, object/evidence checksum, and reviewer/approval reference;
- a classification, authorized audience, retention class, policy version, and expiry/hold state derived from the accepted versioned policy.

It MUST NOT retain raw request/response bodies, tenant object/attachment/source/export bodies, prompts/completions/transcripts, hidden reasoning, credentials, cookies/headers, signed URLs/tokens, raw object keys, host paths, unrestricted stacks/provider payloads, or foreign-tenant metadata. A canary match, unknown field, unsupported classification, failed audience check, or redaction uncertainty drops the payload and fails the applicable evidence gate. Security investigation of prohibited content uses a separately authorized, expiring evidence object; its existence does not permit copying the content into ordinary CI, logs, or release evidence.

All evidence lifecycle dates MUST be calculated from an immutable policy version. Until DEC-013 is accepted, configuration is finite, explicit, minimum-necessary, and fail-closed, but no value is a Product/legal promise.

## Replay and reconciliation modes

| Mode                         | Permitted behavior                                                                                                                                                     | Prohibited behavior                                                                                                      |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `STATE_RECONSTRUCTION`       | Read authoritative rows, immutable object references/checksums, ordered events, and manifests; report gaps and the current legal state.                                | Mutation, invocation, URL issuance, deletion/restore action, or inference of missing success.                            |
| `OFFLINE_REPRODUCTION`       | Use exact allowed immutable inputs, deterministic local provider, simulated tools, isolated storage, and a separate evidence identity.                                 | Network access, paid/external calls, product mutation, or a claim that an opaque external model is bitwise reproducible. |
| `CONTROLLED_REEVALUATION`    | Create a new evaluation identity against an immutable candidate and new exact evaluator/rubric/provider manifest.                                                      | Rewriting the original evaluation, approval, artifact, run state, or Founder decision.                                   |
| `SIDE_EFFECT_RECONCILIATION` | With separate authorization, inspect/cancel/query an existing provider/tool/object effect by stable idempotency key and append the observed outcome/recovery decision. | Blind repetition, double charge, changed tenant/digest, or treating an unknown result as success.                        |

Deletion, expiry, grant revocation, outbox/inbox consumption, object promotion, and restore reconciliation use tenant-bound idempotent jobs with immutable first-outcome evidence. A retry with the same business digest converges; a changed digest conflicts and never reuses prior authority.

## Non-waivable readiness checks

The following conditions are cumulative:

1. **AICO-003 architecture acceptance:** ADR-007 remains Proposed until identifiable Architecture and Product/Security owners approve the exact semantics and explicitly keep DEC-013 open. The document validator and canonical verifier must pass on the exact clean SHA, followed by independent QA/Security approval.
2. **Surface readiness:** every implemented surface runs all applicable stable `A3-T-*` cases. Missing, skipped, quarantined, flaky, redaction-failed, or unavailable required evidence is `BLOCKED`.
3. **Data readiness:** policy version, tenant authority, exact resource version/checksum, lifecycle/deletion/hold state, and required reconciler health are present. Ambiguity denies access/effect.
4. **Restore readiness:** an isolated restore cannot serve traffic, issue signed access, resume work, become model context, or publish preview/export until reconciliation proves tenant scope, checksums, tombstones, holds, ordering, deduplication, and invocation/budget integrity.
5. **Release readiness:** no confirmed cross-tenant disclosure, prohibited telemetry/evidence value, unauthorized external effect, unknown uncontained side effect, duplicate logical cost/effect, resurrection, unreadable lineage, or unresolved Critical finding exists.

Passing AICO-003 selects architecture and proof obligations only. It does not mark later implementation or private-alpha readiness complete.

## Audit conclusion

No AEO objection blocks presenting the AICO-003 package for its required human architecture decision. Acceptance must preserve the present-versus-required truth above, the immediate-revocation limitation of raw provider-signed URLs, the four safe replay modes, the restore/deletion/hold fail-closed rules, and the open DEC-013 duration decision. Any claim that the current MinIO, migration, HTTP, logging, or AICO-002 resilience fixtures prove full AICO-003 implementation would fail `A3-AEO-08`, `A3-AEO-10`, `A3-AEO-11`, and `A3-AEO-12`.
